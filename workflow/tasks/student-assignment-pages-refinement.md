## Outcome and scope

Make the student's assignment list and assignment detail feel deliberate and easy to scan while fitting the existing product. Today the list groups assignments by class in tables with title, due date and solved count; the detail page shows a title, due date, optional Markdown description and an ordered question table with a check for solved questions. Both are functional but have limited visual hierarchy.

Proposed scope: `/student` and `/student/assignments/:aid`, primarily `frontend/src/features/student/AssignmentsPage.tsx` and `AssignmentPage.tsx`, plus focused tests and the student frontend spec if the approved presentation or behavior requires an update. Improve class and assignment hierarchy, due-date and solved-count readability, assignment description, question list and progress presentation. Preserve the existing system font, neutral surfaces, blue accents, modest borders and shared header. Keep teacher/admin changes minimal; avoid changing shared primitives unless necessary and assess their effects if changed.

Decisions already settled: keep the maximum at three ordered, distinct questions; preserve backend contracts and teacher workflows. The question workspace's existing results, submission, complexity and help presentation is acceptable and outside this task; its help already appears on hover, focus or activation. Login implementation and the chosen login prototype are separate work. No backend, API, authorization, database, AI, judge, editor or draft changes are requested.

Approved visual direction: use the prototype's **proposed** views of the assignments list and assignment detail as a design reference for stronger class headings, spaced assignment rows, readable due/solved information, explicit question status and an assignment progress summary. Treat sample titles, counts and dates as illustrative. A progress bar is optional only if its text equivalent is always visible and the count is accurate. Do not label an assignment “not started” based solely on zero solved questions; do not infer attempts or submission state from solved counts. Omit the prototype’s “Continue to questions” control; each question is directly accessible. Existing grouping, ordering, navigation, past-due/closed meaning and Markdown safety remain intact.

Spec delta: approved student-facing presentation adds explicit unsolved status and may add progress summary/counts computed from existing question data. When implemented, update the student frontend spec to describe the resulting presentation without altering the 1–3 question contract. No API or security boundary change is proposed.
